# Запуск в Termux командой trade

Установка рассчитана на **64-битный Android** с актуальным Termux из
[F-Droid](https://f-droid.org/packages/com.termux/) или
[официальных релизов](https://github.com/termux/termux-app/releases).
Root и Docker не нужны. Используется отдельная Ubuntu 24.04 через официальный
[proot-distro](https://github.com/termux/proot-distro), Python 3.12 и Linux wheels NumPy,
pandas, PyArrow и Streamlit. Это позволяет избежать сложной сборки зависимостей под Android.
Ориентир по свободному месту: 2–3 ГБ для установки и дополнительное место для истории/БД.

## Установить один раз

В обычном Termux, снаружи любых Ubuntu/proot-сессий:

```bash
pkg update -y
pkg upgrade -y
pkg install -y git
cd ~
git clone https://github.com/ViGetTo/binance-smart-trader.git
cd binance-smart-trader
bash scripts/termux-install.sh
```

Не запускайте установку из `/sdcard` или Android Download: виртуальному окружению нужны
символические ссылки и Linux filesystem. Клонирование в `~` Termux подходит.
Первая установка скачивает Ubuntu и Python-пакеты; дождитесь сообщения об успешном завершении.
Установщик не запускает торговлю. При повторном запуске `.env`, риск-настройки и SQLite
не перезаписываются. Существующая пользовательская Ubuntu не используется: контейнер
этого проекта называется `smart-trader`.

Если репозиторий впоследствии станет приватным, перед clone выполните:

```bash
pkg install -y gh
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
```

Авторизация выполняется на вашем телефоне через GitHub. Не вставляйте пароли или токены
в URL репозитория и не отправляйте их в чат.

## Запуск

Из любого каталога Termux:

```bash
trade
```

Команда запускает фоновую сессию tmux с ботом и панелью. В браузере этого же телефона откройте:

**http://127.0.0.1:8501**

Сразу проверьте:

```bash
trade status
trade logs
```

В `trade logs` комбинация Ctrl+C закрывает только просмотр журнала. Бот остаётся в фоне.
Повторная команда `trade` не запускает второй экземпляр. Первое сканирование Binance может
занять несколько минут. Существование tmux-сессии не означает, что Binance доступен:
смотрите `trader_heartbeat_age_seconds`, ошибки, режим и heartbeat в панели.

## Режим и ключи

По умолчанию включён **PAPER**: реальные публичные котировки Binance, виртуальные 10 000 USDT.
Ключи для PAPER не нужны. LIVE-режима нет.

Для настоящего Binance Spot Demo:

```bash
trade config
```

В редакторе nano задайте `TRADER_MODE=DEMO`, `BINANCE_DEMO_API_KEY` и
`BINANCE_DEMO_API_SECRET` из [Demo Management](https://demo.binance.com/en/my/settings/api-management).
Сохранить: Ctrl+O, Enter; выйти: Ctrl+X. Порядок переключения при работающем сервисе:
`trade stop`, дождаться подтверждённого завершения, изменить `.env`, `trade`, `trade resume`.
Не переключайте режим при незакрытых DEMO intents. В отсутствие Demo-ключей предусмотрен
явно обозначенный PAPER fallback. Все торговые запросы остаются Demo-only.

Файл ключей: `~/binance-smart-trader/.env`, права 600. Он исключён из Git.
Там же можно добавить Telegram token и chat ID. Другие параметры — `config.toml`.

## Команды управления

| Команда | Действие |
|---|---|
| `trade` | Запустить сервис в фоне или показать уже работающую сессию |
| `trade status` | Режим, heartbeat, капитал, позиции, pending intents и причина остановки входов |
| `trade logs` | Последние сообщения и дальнейший вывод; Ctrl+C закрывает только tail |
| `trade check` | Проверка публичной доступности production и Demo endpoints |
| `trade pause` | Запрет новых входов, защита и монитор продолжают работать |
| `trade flatten` | Запрет входов и запрос закрытия всех виртуальных позиций |
| `trade stop` | Запрос закрытия и остановка процессов только после подтверждения отсутствия экспозиции |
| `trade resume` | Запрос проверки ордеров, соединения и риска перед возобновлением входов |
| `trade config` | Редактировать `.env` |
| `trade attach` | Консоль tmux; Ctrl+B, затем D: вернуться в Termux без остановки |
| `trade update` | `git pull --ff-only` и обновление окружения после безопасной остановки |
| `trade help` | Подсказка |

После `trade stop` Kill Switch остаётся включённым. Чтобы снова торговать:

```bash
trade
trade resume
```

Если через 30 секунд закрытие не подтверждено, `trade stop` сообщает это и **оставляет
монитор работать**. Не делайте `tmux kill-session`, не удаляйте Ubuntu или базу данных:
при тайм-ауте/неизвестном ордере/DUST нельзя считать позицию закрытой. Оператору нужно
разобрать причину в панели и сверить Demo UI. `trade stop`, запущенный при неработающем
сервисе, сохраняет запрос; запустите `trade`, чтобы монитор смог его выполнить.

Риск-паузы не обходятся командой resume. Ключи и конфигурация перечитываются при запуске
процесса; при их изменении используйте последовательность stop → изменение → trade → resume.

## Android и непрерывность

Для Termux отключите оптимизацию батареи в настройках Android и разрешите фоновую работу.
Команда запуска запрашивает `termux-wake-lock`; `trade stop` освобождает его после завершения
сессии. Это может влиять на заряд. Wakelock и tmux **не гарантируют**, что Android не завершит
процесс при нехватке памяти, перезагрузке или ограничениях производителя.

Если торговый процесс завершился, supervisor повторяет запуск с задержкой до 60 секунд;
состояние/идемпотентность восстанавливаются из SQLite. Автоматический повтор не снимает
Kill Switch. Панель перезапускается отдельно, не завершая бот при ошибке интерфейса.
Ctrl+C в `trade attach` запрашивает безопасное закрытие, а не немедленное убийство процесса.

Для PAPER остановка Android останавливает и локальные стопы: после восстановления используется
следующая доступная котировка. DEMO OCO сохраняется на стороне Binance, если был подтверждён.
Для непрерывного 30–60-дневного исследования сервер надёжнее телефона.

## Типовые проблемы

- **Binance HTTP 451:** Binance ограничивает доступ из текущего местоположения. Установщик и
  Ubuntu не снимают это ограничение; котировки не заменяются вымышленными.
- **Нет aarch64 wheel / 32-битный Android:** этот путь установки не поддержан; используйте
  64-битный Termux/устройство или Linux-сервер. Не используйте Linux requirements.lock как
  универсальный Android lock-файл — установщик разрешает совместимые пакеты для Ubuntu.
- **Старая proot-distro:** установщик поддерживает старый `--override-alias`; если Ubuntu
  содержит Python ниже 3.12, установка явно остановится. Обновите Termux/proot-distro.
- **Готово, но команды trade нет:** закройте/откройте сессию Termux или выполните `hash -r`.
- **Порт 8501 занят:** освободите его или измените порт в `src/smart_trader/service.py` и
  адрес, который открываете в браузере. Торговый процесс не завершается из-за ошибки панели.
- **Переместили репозиторий:** повторите `bash scripts/termux-install.sh` из нового каталога.

## Границы проверки

Установочные shell-скрипты проверяются синтаксически и тестами с имитацией Termux-команд.
Supervisor проверяется тестами жизненного цикла, безопасной остановки и restart.
Физическое Android-устройство в этой среде отсутствует: полный on-device прогон не выполнен.
Ограничение реального Binance API HTTP 451 из среды разработки остаётся в силе.
