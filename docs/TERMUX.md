# Binance Demo в Termux: trade v0.2

Нужен актуальный 64-битный Termux из F-Droid / официальных релизов, 2–3 ГБ свободного места.
Ubuntu 24.04 устанавливается через официальный proot-distro без root и Docker.

## Первая установка

```bash
pkg update -y && pkg upgrade -y
pkg install -y git
cd ~
git clone https://github.com/ViGetTo/binance-smart-trader.git
cd binance-smart-trader
bash scripts/termux-install.sh
trade config
trade
```

Проект должен находиться в домашнем Linux-каталоге Termux, не в `/sdcard` / Download.
Первое скачивание Ubuntu и зависимостей может занять несколько минут.

## Обновить существующую установку

```bash
cd ~/binance-smart-trader
git pull --ff-only
bash scripts/termux-install.sh
trade config
trade
```

Перед заменой окружения установщик замораживает входы и проверяет БД старой сессии.
Только если нет позиций и незавершённых intents, он закрывает старую tmux-сессию.
При открытой экспозиции обновление остановится: сначала `trade stop` и подтверждение закрытия.
Ключи, риск-параметры и старые базы не удаляются. В новом мастере Binance создаётся отдельный
DEMO-профиль, чтобы прежние PAPER 10 000 не отображались как деньги Binance.

## Мастер trade config

1. **Binance Demo**: скрытый ввод HMAC API key и API secret из
   https://demo.binance.com/en/my/settings/api-management. Мастер может проверить подпись,
   разрешение Spot и фактический свободный USDT баланс через read-only account API.
2. **Telegram**: скрытый ввод token, обычный ввод chat ID, проверка и тестовое уведомление.
   Сначала напишите своему боту `/start`. Тестовое сообщение отправляется только после
   соответствующего выбора в мастере. Работающий бот подхватывает Telegram в течение 10 секунд.
3. **Стратегии**: автоматический выбор или базовая стратегия. Изменение применяется после restart.
4. **Риск**: лимиты основной стратегии, новых листингов и общего размещения капитала.
5. **Статус настройки**: показывает только наличие ключей, никогда сами значения.

Файл `.env` записывается атомарно с правами `600`. Не отправляйте его в чат и GitHub.
Ключи/профиль нельзя менять при работающем боте или открытых intents; Telegram можно настроить отдельно.
После изменения Demo-ключей/стратегий: безопасная остановка → настройка → запуск.

**По умолчанию строгий DEMO.** Без ключей бот не подменяет Binance локальной симуляцией.
Отсутствующий на Demo символ пропускается, PAPER-ордер не создаётся. Production-торговли нет.

Начальный капитал берётся из API при первом запуске. Если API возвращает 4900 свободных USDT,
бот стартует с 4900, а не с 10 000. При следующих запусках история не обнуляется. Экран отдельно
показывает актуальные free/locked средства Binance и результат собственных сделок бота.
Если USDT отсутствуют, нужны виртуальные USDT именно на Spot Demo — не реальное пополнение.

## Терминальная панель

`trade` запускает фоновой сервис и открывает Textual-панель. `Q` закрывает только интерфейс;
мониторинг и подтверждённые OCO продолжают работать. `trade start` запускает только фоновой сервис.

| Команда / клавиша | Действие |
|---|---|
| `trade ui` или `trade stats` | Вернуться к терминальной аналитике |
| `1` / Обзор | Капитал, PnL дня/недели/всего, просадка, график, причины отказов |
| `2` / Позиции | Объём, цена, mark, stop, target, стратегия, venue |
| `3` / Сделки | История, Net PnL, R, причина закрытия |
| `4` / Рынок | Рейтинг монет и причины сигналов |
| `5` / Стратегии | Отдельная статистика breakout / pullback / new listings и достаточность выборки |
| `P` / `trade pause` | Остановить входы, продолжить защиту и монитор |
| `R` / `trade resume` | Запросить проверку состояния перед возобновлением |
| `F` / `trade flatten` | Запрос закрытия виртуальных позиций; в панели есть подтверждение |
| `C` / `trade config` | Мастер настройки |
| `D` / `trade doctor` | Проверка процессов, heartbeat, сети и локального сайта |
| `W` / `trade web` | Включить дополнительный Streamlit сайт |
| `trade status` | Цветной краткий статус без входа в полноэкранный интерфейс |
| `trade logs` | Журнал; Ctrl+C закрывает только просмотр |
| `trade stop` | Закрыть позиции и только потом остановить сервис |
| `trade repair` | Восстановить зависшую сессию, только если БД подтверждает отсутствие экспозиции |
| `trade update` | Обновить остановленный проект и окружение |

Таблицы можно прокручивать клавишами. На узком экране показатели перестраиваются вертикально.
Если нет подтверждённых данных, выводится «—» и понятная причина, а не выдуманный результат.
Автовыбор стратегий не означает поиск гарантированной прибыли: по умолчанию нужны 20 сделок
и 30 дней до использования статистики. Риск не повышается ради «разгона»; при плохих условиях
бот имеет право не торговать.

После `trade stop` Kill Switch остаётся активным. Повторный запуск: `trade`, затем `R` или
из другой сессии `trade resume`. При DUST, неизвестном ордере или недоступном API закрытие
не считается успешным; монитор остаётся работать. БД с активными ордерами удалять нельзя.

## Сайт — дополнительный, терминал от него не зависит

Веб-панель по умолчанию выключена для снижения нагрузки на телефон. Для включения:

```bash
trade web
```

В обычном браузере **того же телефона** откройте http://127.0.0.1:8501 . Не используйте
предпросмотр ссылки внутри чата как доказательство работы локального сервера.
`trade doctor` проверяет HTTP `/_stcore/health`. Здоровый HTTP ответ не гарантирует исправность
браузерного WebSocket; при бесконечном skeleton попробуйте внешний Chrome и проверьте журнал.
Устаревший `use_container_width` заменён на `width="stretch"`; предупреждения не забивают лог.

Если heartbeat устарел на сотни секунд, PID из БД сам по себе не доказывает работу процесса.
Новый статус проверяет живой процесс отдельно. При пустом портфеле `trade repair` безопасно
убирает старую сессию. При позициях/неизвестных заявках он откажется завершать монитор.

## Android и ограничения

Отключите оптимизацию батареи для Termux, разрешите фоновую работу. Запуск удерживает
`termux-wake-lock`, остановка освобождает его. Wakelock и tmux не предотвращают убийство
процессов Android при нехватке памяти или перезагрузке. Телефон может расходовать заряд.

Подтверждённый DEMO OCO находится на Binance. Локальные PAPER-стопы, если этот отдельный
исследовательский режим включён вручную, зависят от запущенного процесса. Сервисы восстанавливают
SQLite-состояние при рестарте; неизвестный результат ордера не повторяется вслепую.
HTTP 451 — ограничение Binance по местоположению, а не проблема Python; оно не обходится.

Локальные unit/integration тесты и Textual pilot прошли. Веб-панель проверяется в настоящем
локальном Chromium на desktop/mobile viewport. Физического Android и ваших Demo-ключей
в среде разработки нет: подпись/исполнение с настоящим аккаунтом нужно проверить на устройстве.
