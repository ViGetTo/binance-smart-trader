# PAPER Lab в Termux: trade v0.3

Три автономных виртуальных счёта по настоящим публичным котировкам Binance. Ключи и
верификация для локального PAPER не нужны. Реальной торговли и кредитного плеча нет.
Нужен актуальный 64-битный Termux из F-Droid / официальных релизов, 2–3 ГБ места.
Ubuntu 24.04 устанавливается через официальный proot-distro без root и Docker.

## Быстро исправить застрявший Demo-профиль (v0.3.1)

Закройте старую панель клавишей Q и выполните:

```bash
cd ~/binance-smart-trader
git pull --ff-only
bash scripts/trade-termux.sh paper
```

Переустановка Ubuntu и ввод ключей не нужны. Команда проверит отсутствие позиций/заявок,
завершит пустой старый сервис, сохранит PAPER-профиль, обновит команду `trade` и запустит
три счёта. Старые базы не удаляются. Обычный `stop` запросит проверку перед возобновлением;
ошибки Risk Manager и ручная пауза сохраняются. Далее доступна команда `trade paper`.
При наличии незавершённых ордеров смена профиля блокируется до их закрытия.

Панель теперь переключает профиль после настройки и при изменении конфигурации извне,
включая вкладку трёх счетов. Сохранённый выбор в `trade config` имеет приоритет над
унаследованными переменными режима Termux; API-ключи при этом не выводятся.

## Первая установка

```bash
pkg update -y && pkg upgrade -y
pkg install -y git
cd ~
git clone https://github.com/ViGetTo/binance-smart-trader.git
cd binance-smart-trader
bash scripts/termux-install.sh
trade
```

Храните проект в домашнем каталоге Termux, не в `/sdcard` / Download.
Скачивание Ubuntu и зависимостей при первой установке занимает несколько минут.

## Переход с v0.2

Остановите старую версию **до** скачивания нового кода:

```bash
trade stop
cd ~/binance-smart-trader
git pull --ff-only
bash scripts/termux-install.sh
trade config
```

В мастере: **1 → 1** (свой PAPER), баланс **4900**, затем **0** для выхода.
После этого:

```bash
trade
```

Если старый процесс завис и нет позиций/заявок, `trade repair` проверит БД и закроет сессию.
При открытых позициях сначала дождитесь закрытия: установщик не завершает такой монитор.
Старые базы и `.env` сохраняются. PAPER Lab использует отдельные счета:
`data/paper-lab-accounts/base.sqlite`, `aggressive.sqlite`, `active.sqlite`.
Смена стартового депозита не пополняет существующие счета и не обнуляет результаты.

## Счета и сравнение

| Счёт | Риск обычной сделки | Суммарное размещение | Сигналы | Дневной / недельный лимит |
|---|---:|---:|---|---|
| Базовый | 0.5% | 25% | 15m, строгий breakout / pullback | 2% / 5% |
| Рискованный | 2% | 75% | 15m, объём от 1.4×, цель 3.5R | 10% / 20% |
| Активный | 0.3% | 40% | 5m, пробой 12 свечей, объём от 1.2×, скан раз в минуту | 2% / 5% |

На каждом счёте максимум 3 позиции. New Listings Hunter использует 15m и минимум 4 часа
консолидации во всех профилях: риск не выше 0.2%, одна позиция, размер не выше 5% капитала.
Все профили проверяют BTC 1H, ликвидность, комиссии и net reward/risk. Стопы обязательны.
Рискованный профиль может терять заметно больше. Активный ищет сигналы чаще, но не обязан
открывать сделку при каждом скане. Если условий нет — ноль сделок является корректным результатом.

Все три счёта начинают с одинаковых 4900 виртуальных USDT и платят одинаковые модельные
комиссии/проскальзывание. Балансы не связаны: это три независимых эксперимента, не разделение
4900 между тремя счетами. Параметры доступны в `config.toml`, разделы `[paper_profiles.*]`.
Изменение стратегии требует остановки и нового запуска. Статистика прежней конфигурации не стирается.

## Ночной запуск

```bash
trade
```

`Q` закрывает только интерфейс. Оставьте Termux работать; сервис остаётся в tmux.
Выключите оптимизацию батареи для Termux и разрешите фоновую работу. Используется
`termux-wake-lock`, но Android всё равно может завершить процесс при нехватке памяти или перезагрузке.
PAPER-стопы требуют работающего процесса и сети. После простоя исполнение происходит по
доступному актуальному стакану; пропущенные сделки и цены не придумываются задним числом.

Утром:

```bash
trade report
trade ui
```

Отчёт показывает капитал, PnL с открытыми позициями, число закрытых/открытых сделок,
просадку и расходы каждого счёта. Подробности: комиссии, slippage, PF, Win Rate,
Expectancy R и причины отказов в CLI. JSON обновляется каждые 30 секунд:
`data/reports/paper-comparison.json`. Если котировки устарели, оценка капитала тоже остаётся
последней доступной — это отмечено статусом. Одна ночь недостаточна для выводов о доходности.

## Команды и клавиши

| Команда / клавиша | Действие |
|---|---|
| `trade` | Проверить GitHub, запустить сервис, открыть CLI |
| `trade start` | Запустить только фоновой сервис |
| `trade ui` / `trade stats` | Открыть CLI без установки обновлений |
| `0` | Таблица трёх счетов |
| `B` / `A` / `T` | Детали базового / рискованного / активного |
| `1` / `2` / `3` / `4` / `5` | Обзор / позиции / сделки / рынок / стратегии выбранного счёта |
| `P` / `trade pause` | Остановить новые входы на ВСЕХ счетах, сохранить монитор |
| `R` / `trade resume` | Проверить риск/данные и возобновить входы на всех счетах |
| `F` / `trade flatten` | Запрос закрытия всех виртуальных позиций |
| `Q` | Закрыть только CLI, оставить сервис |
| `C` / `trade config` | Настройки |
| `trade report` / `trade status` | Сравнение и состояние без полноэкранного интерфейса |
| `trade doctor` / `trade logs` | Диагностика / журнал; Ctrl+C закрывает просмотр |
| `trade stop` | Закрыть позиции и после подтверждения остановить сервис |
| `trade repair` | Остановить зависшую сессию только при отсутствии экспозиции на всех счетах |
| `trade update` | Проверить и установить обновление вручную после остановки |
| `W` / `trade web` | Необязательная веб-панель http://127.0.0.1:8501 |

После `trade stop` Kill Switch сохраняется. При новом запуске выполните `trade resume`
или нажмите `R`, если хотите разрешить входы. Ни рестарт, ни восстановление сети не снимают
ручную остановку или остановку из-за ошибки Risk Manager. При DUST/неопределённой заявке
закрытие не считается успешным; монитор не завершается до подтверждения.

## trade config

- **1 → 1:** отключить Binance-аккаунт, выбрать три локальных PAPER-счёта. Публичные
  котировки остаются включены. Сохранённые Demo-ключи не отправляются.
- **1 → 2:** необязательное подключение Binance Spot Demo HMAC key/secret. Работает только
  на `demo-api.binance.com`; реальные средства недоступны боту.
- **1 → 3:** полностью включить/выключить публичные котировки Binance. При OFF нет
  REST/WebSocket/Alpha запросов, новых исполнений и обновления цен. Это требует остановленных,
  пустых счетов; без источника котировок торговля невозможна.
- **2:** Telegram token/chat ID, проверка и тестовое сообщение. Работающий сервис подхватывает
  их в течение 10 секунд. Уведомления подписаны названием PAPER-счёта.
- **3:** выбор стратегии по прошлой статистике / базовая. Недостаточная история не считается
  подтверждением прибыльности; требуется не менее 20 сделок и 30 дней по умолчанию.
- **4:** уменьшить риск выбранного счёта в пределах его профиля.
- **5:** статус настроек без раскрытия ключей.
- **6:** включить/выключить автоматические обновления.

`.env` записывается атомарно с правами `600`; он и базы не попадают в GitHub.

## Автообновление

При каждом `trade` / `trade start` выполняется ограниченная по времени проверка `origin/main`
в `ViGetTo/binance-smart-trader`. При наличии обновления и остановленном сервисе: fast-forward,
установка Python-зависимостей, проверка окружения и обновление команды `trade`. Если нет сети,
действующая версия продолжает использоваться. При работающей tmux-сессии обновление только
обнаруживается; установка откладывается до `trade stop` и следующего запуска.
Локальные изменения отслеживаемых файлов сохраняются: установка при них пропускается.
Автоматического stash/reset/clean нет. Если установка зависимостей не завершилась, новый
сервис не запускается до успешного повторения `trade update`.

Публичные данные должны быть доступны на устройстве. HTTP 451 — ограничение Binance,
которое бот не обходит; результаты при отсутствии данных не подменяются вымышленными.
Физическое Android-устройство и длительный ночной прогон в среде разработки не проверены.
