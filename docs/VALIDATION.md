## Что подтверждают тесты

- Отсутствие LIVE-режима, ключей у публичного клиента, production-торговых запросов,
  редиректов и альтернативных демодоменов.
- HMAC-подпись, отсутствие повторов POST при HTTP 5xx/408/-1007/transport timeout,
  обработка GET rate limit и HTTP 451.
- Decimal lattice для LOT_SIZE / MARKET_LOT_SIZE, tickSize, notional, процентных
  ограничений, MAX_POSITION и ограничений количества ордеров.
- Только завершённые свечи; отбрасывание разрывов, дубликатов, NaN и некорректного OHLC.
- Рыночный фильтр, breakout/volume, период наблюдения новых листингов, bounded ranking.
- Размер позиции, 0.5%/0.2%, 25%/5%, дневной/недельный stop, корреляция, cooldown,
  duplicate signal, kill и остановка при ошибке Risk Manager.
- PAPER lifecycle с комиссиями, частичное исполнение, flatten, восстановление после
  crash между учётом исполнения и финализацией сделки, stale book.
- DEMO lifecycle с имитацией HTTP: preflight → BUY → myTrades → OCO → stop → учёт PnL.
- Отклонение OCO → безопасное закрытие, частичный защитный fill → отмена → остаток SELL,
  потерянный ответ принятого OCO → восстановление без повторной отправки,
  неизвестная отмена → отсутствие конфликтующего SELL.
- Kill Switch во время preflight и на границе отправки блокирует покупку.
- Комиссия покупки в базовом активе вычитается из продаваемого остатка.
- Новая монета без Demo symbol явно сохраняется как PAPER.
- Сигналы/сделки прошлого не меняются при изменении будущих баров.
- Stop-first, расходы, бенчмарки, недопустимость неявных допущений о глубине,
  disjoint walk-forward, `null` для неопределённых метрик, атрибуция PnL стратегий.
- Streamlit и persistence control, reconnect WebSocket, различие first_seen/market age,
  Telegram outbox и ограничение повторов одинаковых аварийных уведомлений.
- Суточный отчёт относится к завершённым UTC суткам и не включает следующий день.
- Termux: отдельный Ubuntu alias и правильный Android shebang, command из любого каталога,
  отсутствие shell injection в пути проекта, запрет обновления работающего сервиса,
  остановка только после закрытия intents, сохранение Kill Switch при повторном старте,
  автоматический повтор торгового процесса без остановки панели.

Эти проверки подтверждают локальную реализацию перечисленных сценариев. Они не подтверждают
совместимость со всеми будущими изменениями API, отсутствие всех возможных дефектов,
доходность стратегии или эквивалентность модели исполнения настоящему matching engine.

решений с реальными закрытыми свечами. Для DEMO использовать только ключи Demo Management,
проверить BUY, OCO, частичные исполнения, kill/flatten, рестарт и сброс сети на небольшом
виртуальном бюджете. Не удалять БД с активными ордерами. После устранения расхождений
накапливать 30–60 дней наблюдений, достаточное число сделок и архив universe; затем оценить

«данных недостаточно».
